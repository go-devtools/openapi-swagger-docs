## Decision procedure

1. Capture command, installed version, target, build tags, stdout, stderr and exit code.
2. Read diagnostic code, severity, source, route, facts and fix fields.
3. Compare source types, actual codec and declarations; do not scrape Swagger UI for contracts.
4. Correct inaccurate comments or add a centralized public extension for unsupported behavior.
5. Regenerate, check complete generated bytes, and validate actual positive and negative samples.

## Required distinctions

`openapi.generate.stale` requires regeneration, not manual generated-file edits. `openapi.comment.type` means the declared constraint conflicts with the inferred wire type; inspect business intent before changing it. `gin-swagger.handler.ambiguous` requires identity evidence, not an invented operation key.

## Offline resources

`CheckWithOptions` receives explicit BaseURI, Resources and ExampleResources. Never fetch missing references during checking. Keep input size, depth and node budgets bounded. A resource or budget diagnostic is not permission to return a partial contract as complete.

## Completion evidence

Source freshness, structural validity and actual sample agreement are separate claims. Keep `implementation: "not-proven"` in provenance. Install a fixed CLI when exact native exit codes matter. Runtime Build must still succeed for selected actual routes.
